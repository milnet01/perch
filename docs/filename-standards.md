# Filename & naming standard

Naming conventions for files and directories across the Perch tree. These
describe the patterns already in use — grep before adding a file that doesn't
fit one of them.

## Docs (`docs/`)

Two kinds of document, distinguished by filename:

- **Numbered design docs** — `NN-topic.md`, zero-padded two-digit prefix,
  kebab-case topic. The sequence is the reading order and is stable:
  `00-overview.md`, `01-architecture.md`, `02-state-format.md` … through
  `11-roadmap.md`. A new design doc takes the next free number.
- **Non-numbered standards / process docs** — plain kebab-case, no prefix:
  `dependency-policy.md`, `contributing-dev-setup.md`, `coding-standards.md`,
  `filename-standards.md`. Use this for cross-cutting policy that isn't part of
  the numbered design narrative.
- Asset subdirs are plain lowercase: `docs/screenshots/`, `docs/testing/`.

## Python source (`src/perch/`)

- **Modules and packages are `snake_case`**: `state_store.py`, `sni_probe.py`,
  `logging_setup.py`. Packages are directories with an `__init__.py`.
- The package is laid out by role: `core/` (backend-agnostic logic), `ui/`
  (Qt widgets, tray, models), `backend/` (per-compositor backends), `config/`
  (config subsystem). Top-level entry points: `__main__.py` (CLI),
  `app.py` (async `main()`).
- **Backends follow a sub-layout**: `backend/<name>/backend.py` holds the
  `WindowBackend` implementation, with siblings named by concern — the set
  varies per backend (e.g. `outputs.py`, `identity.py` under `x11/`;
  `protocol.py`, `service.py`, `hotkeys.py` under `kwin/`), not a fixed roster
  every backend carries. `<name>` is the compositor slug (`x11`, `kwin`,
  `sway`, `hyprland`, `mutter`).
- Classes `CamelCase`, functions/vars `snake_case`, module-level constants
  `UPPER_SNAKE` (`LOG_MAX_BYTES`, `TOPOLOGY_DEBOUNCE_SECONDS`).

## Tests (`tests/`)

- Test files are **`test_*.py`** (`test_config_loader.py`,
  `test_reducer.py`). pytest `testpaths = ["tests"]`.
- Test tree **mirrors the source subsystems**: `tests/core/`,
  `tests/backend/`, `tests/ui/`, each with its own `__init__.py` and, where
  needed, a local `conftest.py`. Shared fixtures live in the top-level
  `tests/conftest.py` and `tests/fixtures/`.
- Live-integration tests carry a marker in their name/registration, not a
  filename convention: `-m x11` (Xvfb + openbox), `-m kwin` (private dbus +
  `kwin_wayland`). See `[tool.pytest.ini_options]` markers.

## Application data (`data/`)

- The app is identified by the **reverse-DNS app-id
  `io.github.milnet01.Perch`**, and desktop-integration files are named after
  it verbatim: `io.github.milnet01.Perch.desktop`,
  `io.github.milnet01.Perch.metainfo.xml`.
- Icons live under a freedesktop **hicolor theme tree**:
  - App icon: `data/icons/hicolor/scalable/apps/io.github.milnet01.Perch.svg`
    (matches the desktop file's `Icon=` key).
  - Tray/status icons: `data/icons/hicolor/symbolic/status/perch-tray-symbolic.svg`
    plus the `-warning-` and `-error-` state variants — `perch-*-symbolic.svg`,
    kebab-case, `symbolic/status/` for monochrome themable glyphs.
- The wheel maps these to `share/icons`, `share/applications`, `share/metainfo`
  via `[tool.hatch.build.targets.wheel.shared-data]` — keep the source paths
  aligned with that mapping.

## Translations (`translations/`)

Qt Linguist sources are **`perch_<lang>.ts`** (`perch_en.ts`); `<lang>` is the
locale code. Regenerated by `scripts/i18n-update.sh`.

## Packaging (`packaging/`)

- One directory per distribution channel: `packaging/<channel>/`
  (`flathub/`, `rpm/`, `aur/`, `kde-store/`, `appimage/`, `submit/`).
- Recipe files use each channel's native name — `perch.spec` (RPM),
  `PKGBUILD` / `.SRCINFO` (AUR, with a `perch-git/` variant pair alongside the
  release recipe), `io.github.milnet01.Perch.yml` (Flathub manifest, app-id
  named). Submission runbooks live under `packaging/submit/` — one per target,
  named `<target>.sh` for scripted submits (`aur.sh`, `obs.sh`,
  `flathub.sh`) or `<target>.md` for prose runbooks (`kde-store.md`).

## Shell & helper scripts

- Dev helpers live in `scripts/`: shell helpers are `kebab-case.sh`
  (`i18n-update.sh`), Python helpers `kebab-case.py`
  (`render-screenshots.py`). One-off CI/audit tools live in `tools/`
  (`intent_dispatch_audit.py`, snake_case as an importable-style script).
- The push-gate script `local_CI.sh` sits at the repo root and must stay in
  lockstep with `.github/workflows/ci.yml`.
